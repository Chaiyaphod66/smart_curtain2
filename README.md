# Smart Curtain Prototype

เว็บแอปต้นแบบสำหรับควบคุมม่านอัจฉริยะหนึ่งชุด พัฒนาด้วย Next.js และ TypeScript และเชื่อมต่อกับ ESP32 เพื่ออ่านค่าเซ็นเซอร์ ควบคุมมอเตอร์ ตรวจ Encoder และตรวจลิมิตสวิตช์

> สถานะปัจจุบัน: ระบบ Manual, Auto Preset และ Model A ใช้งานบน ESP32 จริงได้แล้ว Auto ทำงานต่อเมื่อปิดหน้าเว็บ แต่จะหยุดมอเตอร์และกลับ Manual เมื่อ ESP32 รีบูตหรือหลุด Wi-Fi

> เอกสารสำหรับพัฒนาต่อและอ้างอิงรายงาน: [สารบัญ Developer Notes](docs/README.md) ครอบคลุม Auto ปัจจุบัน, Model A, [ฮาร์ดแวร์/Safety](docs/05-hardware-safety-and-validation.md) และ[แผนที่โค้ด](docs/06-report-code-map.md)

> การปรับลูปตรวจลิมิตครั้งล่าสุดคอมไพล์ผ่านแล้ว แต่ยังไม่ได้อัปโหลดหรือวัดเวลาหยุดจริงกับชุดม่าน จึงยังไม่ถือว่าผ่านการทดสอบฮาร์ดแวร์

## ความสามารถปัจจุบัน

### หน้าสำหรับผู้ใช้

- `/` ภาพรวมสถานะม่าน อุปกรณ์ และสภาพแวดล้อม
- `/control` สลับ Manual/Auto ตามสถานะจริงใน ESP32, เลือก Auto Preset แบบภาษาง่าย และควบคุมตำแหน่งม่านเมื่ออยู่ใน Manual
- `/environment` แสดงอุณหภูมิ ความชื้น และความเข้มแสง
- รองรับหน้าจอคอมพิวเตอร์และโทรศัพท์

### หน้า Developer

หน้า `/dev` รวมเครื่องมือสำหรับพัฒนาและตรวจระบบ ได้แก่

- สถานะ ESP32 และเครือข่าย
- ข้อมูลเซ็นเซอร์จริงหรือข้อมูลจำลอง
- ควบคุมมอเตอร์และตำแหน่งม่าน
- ทดสอบ Encoder A/B
- ทดสอบลิมิตด้านเปิดและด้านปิด
- ตั้งจุดอ้างอิงปิด–เปิดสำหรับคำนวณตำแหน่ง 0–100%
- บันทึกผลการเคลื่อนที่และส่งออก Motion Log
- ออกแบบและทดลอง Auto Preset

### Auto Preset

- มี Preset เริ่มต้น: ตามอุณหภูมิ, ตามแสงธรรมชาติ, สมดุลอัตโนมัติ และกำหนดเอง
- หน้า User เลือกจากคำอธิบายแบบภาษาคนได้ โดยไม่ต้องกรอกค่า °C หรือ lux
- หน้า `/control` มี 3 แนวทาง แนวทางละ 3 ชุดย่อย รวม 9 ชุด เลือกแล้วกดใช้ชุดนี้ได้โดยไม่ต้องสร้างหรือบันทึกเอง
- ผู้ใช้เปิด “ปรับเกณฑ์ Auto” เพื่อแก้อุณหภูมิ ช่วง lux ตำแหน่งม่าน จำนวนรอบยืนยัน และ Cooldown ของแต่ละชุดได้ ค่าที่แก้เก็บแยกต่อชุดใน `localStorage` และผ่านกฎตรวจสอบก่อนส่งไป ESP32
- ระบบเทียบ preset ID และ config revision ก่อนส่งค่า หากตรงกับ ESP32 จะเปิด Auto โดยไม่ส่ง config ซ้ำ; ESP32 เก็บชุดที่ใช้งานล่าสุด จึงยังต้องส่งค่าเมื่อสลับไปชุดอื่น
- ค่าชุดย่อยเป็นค่าทดลองของต้นแบบ ต้องตรวจและปรับตามห้องจริง ไม่ใช่เกณฑ์ความสบายที่ยืนยันจากงานวิจัย
- หน้า Dev ซ่อนตัวเลขไว้ในส่วนการตั้งค่าขั้นสูง และใช้ค่าแนะนำได้ทันที
- เมื่อเลือก `สมดุลอัตโนมัติ` หน้า Dev จะแสดง Model A ซึ่งให้อุณหภูมิกำหนดงบแสง ใช้ hysteresis และปรับม่านเป็น step พร้อมนโยบายร้อน + มืดให้คงตำแหน่ง
- Model A อยู่ใน firmware และใช้เป็น Auto ต่อเนื่องได้ โดยยืนยันผล 2 รอบ ขยับทีละ Step และพัก 15 วินาที จึงทำงานต่อได้แม้ปิดหน้าเว็บ; ส่วนหน้า Dev ใช้ตรวจเหตุผลและสถานะการตัดสินใจของ Logic เดียวกัน
- เลือกใช้อุณหภูมิ แสง หรือทั้งสองอย่างได้
- แบ่งช่วงแสงได้ 2–5 ช่วง พร้อมกำหนดตำแหน่งม่านของแต่ละช่วง
- ตั้งจำนวนค่าที่ต้องยืนยันติดต่อกัน 1–10 ครั้ง
- ตั้ง Cooldown หลังมอเตอร์หยุดได้ 0–3600 วินาที
- ไม่ส่งคำสั่งเมื่อ ESP32 ออฟไลน์, Encoder ยังไม่พร้อม, ลิมิตขัดแย้ง, มอเตอร์กำลังทำงาน หรือมี Motor Fault
- บันทึกพรีเซ็ตลงหน่วยความจำถาวรของ ESP32 และตรวจ Dry run ก่อนเปิด Auto ต่อเนื่อง
- เมื่อเปิด Auto แล้ว Logic ทำงานบน ESP32 จึงไม่ต้องเปิดหน้าเว็บค้างไว้
- คำสั่ง Manual, STOP, การตั้ง Calibration, Motor fault, การรีบูต หรือ Wi-Fi Station หลุด จะยกเลิก Auto เพื่อความปลอดภัย
- เมื่อ Wi-Fi หลุดระหว่างมอเตอร์ทำงาน ESP32 จะสั่งเบรก/หยุดทันที บันทึกสาเหตุ `network-lost` และไม่เปิด Auto กลับเองหลังเชื่อมต่อใหม่

### คำสั่งเสียง

- หน้า `/control` รับคำสั่งเสียงภาษาไทยผ่านความสามารถของ browser
- รองรับตำแหน่ง 0–100 จากตัวเลขที่ระบบรู้จำเสียงส่งกลับมา เช่น “ช่วยเปิดม่าน 75% หน่อยครับ” รวมถึงเลขไทย เช่น `๗๕`
- กรองประโยคปฏิเสธและคำสั่งกำกวม โดยจะไม่เดาหรือขยับม่านเอง
- ผู้ใช้เพิ่มวลีของตนเองแล้วผูกกับ STOP, Manual, ตำแหน่ง, Auto Preset หรือ Model A ได้
- เมื่อรู้จำคำสั่งสำเร็จ เว็บจะส่งคำสั่งทันทีโดยไม่ต้องกดยืนยัน แต่ยังผ่านการตรวจโหมด ลิมิต Encoder, Calibration และ motor fault ก่อนทำงาน; STOP ส่งทันทีเช่นเดิม
- วลีที่ผู้ใช้เพิ่มเก็บใน `localStorage` ของ browser เครื่องนั้น จึงไม่ซิงก์ข้ามอุปกรณ์และไม่ต้องใช้ฐานข้อมูล

## เทคโนโลยี

- Next.js 16 (App Router)
- React 19
- TypeScript 5
- CSS Modules
- Node.js 20.9.0 ขึ้นไป
- Node.js Test Runner และ ESLint

โปรเจกต์นี้ยังไม่ใช้ฐานข้อมูล โหมดที่เลือก ประวัติการเคลื่อนที่ และวลีคำสั่งเสียงที่เพิ่มเองเก็บใน `localStorage` ส่วนพรีเซ็ตที่เปิดใช้งานจริงเก็บใน NVS/Preferences ของ ESP32

## เริ่มต้นใช้งาน

### 1. ติดตั้ง Dependencies

```bash
npm install
```

### 2. ตั้งค่าแหล่งข้อมูล

สร้างไฟล์ `.env.local` ที่ root ของโปรเจกต์

ใช้ ESP32 จริง:

```env
SENSOR_SOURCE=esp32
ESP32_BASE_URL=http://192.168.1.123
NEXT_PUBLIC_ESP32_BASE_URL=http://192.168.1.123
```

เปลี่ยน IP ให้ตรงกับ IP ของ ESP32 ในเครือข่ายเดียวกัน

- `ESP32_BASE_URL` ใช้โดย Next.js API สำหรับอ่านสถานะและเซ็นเซอร์
- `NEXT_PUBLIC_ESP32_BASE_URL` ใช้โดยเบราว์เซอร์สำหรับส่งคำสั่งควบคุมไปยัง ESP32 โดยตรง
- ตัวแปรที่ขึ้นต้นด้วย `NEXT_PUBLIC_` จะถูกส่งไปฝั่งเบราว์เซอร์ จึงห้ามใส่รหัสผ่านหรือข้อมูลลับ

ใช้ข้อมูลจำลองโดยไม่ต้องต่อ ESP32:

```env
SENSOR_SOURCE=mock
```

### 3. เปิด Development Server

```bash
npm run dev
```

จากนั้นเปิด:

- หน้าใช้งาน: [http://localhost:3000](http://localhost:3000)
- หน้า Developer: [http://localhost:3000/dev](http://localhost:3000/dev)
- Sensor API: [http://localhost:3000/api/sensors](http://localhost:3000/api/sensors)
- Device Status API: [http://localhost:3000/api/device-status](http://localhost:3000/api/device-status)

## การเชื่อมต่อ ESP32

เว็บคาดว่า ESP32 จะมี HTTP endpoints ต่อไปนี้:

| Method | Endpoint | หน้าที่ |
| --- | --- | --- |
| `GET` | `/sensors` | อ่านอุณหภูมิ ความชื้น และความเข้มแสง |
| `GET` | `/status` | อ่านสถานะมอเตอร์ เครือข่าย Encoder ลิมิต และ Calibration |
| `POST` | `/motor/open` | ขยับม่านไปทางเปิดแบบ Jog |
| `POST` | `/motor/close` | ขยับม่านไปทางปิดแบบ Jog |
| `POST` | `/motor/stop` | หยุดมอเตอร์ |
| `POST` | `/motor/position?percent=50` | ไปยังตำแหน่งเป้าหมาย 0–100% |
| `POST` | `/motor/open-until-limit` | ทดสอบขยับจนพบลิมิตด้านเปิด |
| `POST` | `/motor/close-until-limit` | ทดสอบขยับจนพบลิมิตด้านปิด |
| `POST` | `/calibration/closed` | บันทึกตำแหน่งปิด |
| `POST` | `/calibration/open` | บันทึกตำแหน่งเปิด |
| `POST` | `/calibration/reset` | ล้างค่า Calibration |
| `GET` | `/auto/status` | อ่านสถานะ Auto Runtime ใน ESP32 |
| `POST` | `/auto/config?...` | ตรวจและบันทึกพรีเซ็ตลง ESP32 โดยปิด Auto ไว้ก่อน |
| `POST` | `/auto/enable` | เปิด Auto ต่อเนื่องหลังผ่านเงื่อนไขความปลอดภัย |
| `POST` | `/auto/disable` | ปิด Auto และหยุดคำสั่ง Auto ที่กำลังทำงาน |

การไหลของข้อมูลโดยย่อ:

```text
Sensor/Status: ESP32 -> Next.js API -> React UI
Manual command: React UI -> ESP32 HTTP API -> Motor driver
Always-on Auto: ESP32 sensors -> ESP32 Auto Runtime -> existing position control
Safety status: Limit + Encoder + Motor fault -> ปิดกั้นคำสั่งที่ไม่ปลอดภัย
```

## โครงสร้างโปรเจกต์

```text
app/
  (user)/                 หน้าใช้งานหลัก ภาพรวม ควบคุม และสภาพแวดล้อม
  api/                    API กลางสำหรับเซ็นเซอร์และสถานะอุปกรณ์
  dev/                    หน้าเครื่องมือสำหรับ Developer
components/
  user/                   UI สำหรับผู้ใช้ทั่วไป
  dashboard/              แผงควบคุมและเครื่องมือทดสอบฮาร์ดแวร์
hooks/                    State, polling, คำสั่งม่าน และประวัติการทำงาน
lib/
  curtain/                Logic ม่าน Auto Preset, Auto Runtime และ ESP32 client
  sensors/                แหล่งข้อมูล Mock และ ESP32
types/                    TypeScript types ของข้อมูลระบบ
docs/PROJECT_PLAN.md      แผนพัฒนาโครงการ
```

Firmware ของ ESP32 เป็นอีกโปรเจกต์หนึ่งและไม่ได้อยู่ใน repository เว็บนี้

## การตรวจสอบก่อนใช้งานกับมอเตอร์จริง

1. ตรวจแหล่งจ่ายไฟและต่อกราวด์ร่วมระหว่าง ESP32 กับ Motor Driver
2. เตรียมปุ่ม STOP และเริ่มด้วยความเร็วมอเตอร์ต่ำ
3. ตรวจลิมิตด้านเปิดและด้านปิดให้ทำงานถูกทิศ
4. ตั้ง Calibration ใหม่เมื่อเปลี่ยนตำแหน่งม่านหรือชุดส่งกำลัง
5. ทดสอบคำสั่งทีละขั้นจากหน้า `/dev` ก่อนใช้หน้า User หรือ Auto Preset

ระบบปัจจุบันออกแบบสำหรับทดสอบในเครือข่ายภายใน ยังไม่มีระบบบัญชีผู้ใช้ การยืนยันตัวตน หรือ Cloud API จึงไม่ควรเปิด ESP32 API ให้อินเทอร์เน็ตเข้าถึงโดยตรง

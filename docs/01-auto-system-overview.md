# ภาพรวมระบบ Auto

## เป้าหมาย

ระบบต้องควบคุมม่านหนึ่งชุดจากอุณหภูมิและความเข้มแสงได้ โดยยังคงให้ผู้ใช้หยุดหรือเปลี่ยนกลับเป็น Manual ได้ตลอด และไม่ให้ Logic ระดับเว็บข้ามระบบความปลอดภัยของอุปกรณ์

## โหมดที่มีอยู่จริงในโปรเจกต์

### 1. Manual

- ผู้ใช้สั่งเปิด ปิด หยุด หรือไปยังตำแหน่งที่ต้องการ
- คำสั่งจากเว็บถูกส่งไป ESP32
- ESP32 เป็นผู้ควบคุมมอเตอร์และตรวจ Encoder/ลิมิต
- ผู้ใช้ยังต้องสามารถกด STOP ได้ทุกเวลา

### 2. เครื่องมือตรวจสอบ Auto บนหน้า Dev

- หน้า `/dev` แสดงค่าที่ใช้ตัดสินใจ เป้าหมาย เหตุผล phase และ fault เพื่อช่วยตรวจระบบ
- การแสดงผลบนหน้า Dev ไม่ใช่วงรอบควบคุมอีกชุดหนึ่ง และไม่ต้องเปิดหน้าเว็บค้างไว้
- เมื่อเปิด Model A หน้าเว็บจะบันทึก Profile และเปิด Auto บน ESP32 ซึ่งเป็นผู้ยืนยันผล ขยับทีละ Step และจัดการ Cooldown

### 3. Auto บน ESP32

- เป็น Auto ที่ทำงานใน firmware ของ ESP32
- ใช้ Auto Preset ที่บันทึกไว้ในอุปกรณ์
- รองรับ Model A บนบอร์ดด้วย โดยมี Endpoint `/auto/model-a` สำหรับบันทึก Profile ก่อนเปิดใช้งาน
- ทำงานต่อได้แม้ปิดหน้าเว็บหรือคอมพิวเตอร์
- หน้าเว็บมีหน้าที่ตั้งค่า เปิด/ปิด ดูสถานะ และทดสอบแบบ Dry run

## เส้นทางข้อมูล

```text
เซ็นเซอร์อุณหภูมิ/แสง
          ↓
        ESP32
  อ่านค่า + ตรวจความปลอดภัย
          ↓
  /status และคำสั่ง HTTP
          ↓
 Next.js API / Client
          ↓
 หน้า User และหน้า Dev
```

เมื่อเปิด Always-on Auto เส้นทางตัดสินใจหลักอยู่ใน ESP32:

```text
เซ็นเซอร์ → Auto Preset ใน ESP32 → ตัวควบคุมตำแหน่ง
          → Encoder / FC-33 / fault → L298N → มอเตอร์
```

หน้าเว็บไม่ควรเป็นจุดเดียวที่รับผิดชอบการหยุดมอเตอร์ เพราะ Wi-Fi หรือเบราว์เซอร์อาจหลุดได้

## ชั้นของระบบ

| ชั้น | หน้าที่ |
|---|---|
| หน้า User | ใช้งานง่าย เลือก Manual/Auto และเลือก Preset |
| หน้า Dev | ตรวจข้อมูลจริง ทดสอบอุปกรณ์ Dry run และดูเหตุผลการตัดสินใจ |
| Next.js API | เป็นตัวกลางระหว่างเบราว์เซอร์กับ ESP32 |
| Auto Logic | แปลงข้อมูลเซ็นเซอร์เป็นเป้าหมายหรือคำสั่งคงตำแหน่ง |
| Motion Control | แปลงเป้าหมายเป็นการหมุนมอเตอร์และติดตาม Encoder |
| Safety | ลิมิต STOP timeout fault และการตรวจความพร้อม |

## ลำดับสิทธิ์ด้านความปลอดภัย

จากสำคัญที่สุดไปน้อยที่สุด:

1. STOP หรือ fault ต้องหยุดการเคลื่อนที่
2. FC-33 ที่ด้านกำลังเคลื่อนไปต้องหยุดมอเตอร์ทันที
3. ข้อมูล Encoder ผิดปกติหรือมอเตอร์ไม่เคลื่อนต้อง timeout
4. Manual ต้องยกเลิก Auto ก่อนรับคำสั่งใหม่
5. Auto จึงค่อยคำนวณตำแหน่งเป้าหมาย

Auto Logic ไม่มีสิทธิ์สั่งให้ข้ามลิมิตหรือยกเลิก fault

## ไฟล์สำคัญ

- `components/dashboard/Dashboard.tsx` — โหมด Manual/Auto Lab บนหน้า Dev
- `components/dashboard/AutoPresetPanel.tsx` — ห้องทดลอง Auto Preset และ Model A
- `lib/curtain/auto-preset.ts` — Logic Auto ปัจจุบันบนเว็บ
- `lib/curtain/closed-loop-auto.ts` — Logic Model A
- `lib/curtain/auto-runtime.ts` — Confirmation, Cooldown และสถานะ runtime ฝั่งเว็บ
- `lib/curtain/esp32-curtain-client.ts` — การสื่อสารกับ ESP32
- `types/auto-preset.ts` — รูปแบบข้อมูล Preset และผลการตัดสินใจ

## สิ่งที่ต้องจำก่อนแก้โค้ด

- อย่าใช้คำว่า Auto เหมือนกันทั้งหมดโดยไม่ระบุว่าเป็น Auto Lab หรือ Always-on Auto
- การแสดงคำแนะนำบนหน้าเว็บไม่เท่ากับการสั่งมอเตอร์
- เมื่อเพิ่ม Logic ใหม่ ต้องมี test ของค่าขอบเขต เซ็นเซอร์หาย และสถานการณ์กลับทิศ
- ก่อนทดสอบมอเตอร์จริง ให้ทดสอบ Dry run และทดสอบ STOP/FC-33 ก่อนเสมอ

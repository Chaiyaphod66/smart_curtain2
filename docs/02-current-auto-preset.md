# Auto Preset ปัจจุบัน

## สถานะ

นี่คือ Logic หลักที่พร้อมใช้งานกับ ESP32 จริง ไม่ใช่ Model A เมื่อบันทึก Preset และเปิด Always-on Auto แล้ว ESP32 จะตัดสินใจต่อเองได้โดยไม่ต้องเปิดหน้าเว็บ

Logic ฝั่งเว็บอยู่ใน `lib/curtain/auto-preset.ts` และใช้สำหรับตรวจค่า อธิบายเหตุผล และ Dry run ให้สอดคล้องกับ firmware

## Preset มาตรฐาน

ระบบมีแนวทางหลักดังนี้:

- **ตามอุณหภูมิ** — ใช้อุณหภูมิเป็นหลัก
- **ตามแสงธรรมชาติ** — ใช้ช่วง lux เป็นหลัก
- **สมดุลอัตโนมัติ** — ตรวจทั้งอุณหภูมิและแสง
- **กำหนดเอง** — ผู้พัฒนาปรับค่ารายละเอียดได้

แต่ละแนวทางสำหรับผู้ใช้มีชุดย่อยสำเร็จรูป เพื่อให้เลือกใช้ได้โดยไม่ต้องเข้าใจค่า lux ทุกค่า

## Logic ของ “สมดุลอัตโนมัติ”

ค่ามาตรฐาน:

| ตัวแปร | ค่า |
|---|---:|
| อุณหภูมิเริ่มปิด | 30°C |
| อุณหภูมิเปิดกลับ | 28°C |
| เป้าหมายเมื่อร้อน | 15% |
| จำนวนค่าที่ต้องยืนยัน | 3 ครั้ง |
| Cooldown หลังขยับ | 120 วินาที |

ช่วงแสง:

| ความเข้มแสง | เป้าหมายม่าน |
|---|---:|
| 0–ต่ำกว่า 600 lux | 90% |
| 600–ต่ำกว่า 800 lux | 65% |
| 800–ต่ำกว่า 1,000 lux | 40% |
| ตั้งแต่ 1,000 lux | 15% |

## ลำดับการตัดสินใจ

```text
1. ตรวจว่า Preset ถูกต้อง
2. ตรวจว่าเซ็นเซอร์ทุกตัวที่เปิดใช้มีค่า
3. ถ้าอุณหภูมิถึงเกณฑ์ปิด → เลือก closedTarget ทันที
4. ถ้ายังไม่ร้อนถึงเกณฑ์ → หาช่วง lux และเลือกเป้าหมายของช่วงนั้น
5. รอผลเดียวกันครบ confirmationReadings ครั้ง
6. ถ้าไม่อยู่ใน Cooldown และระบบพร้อม → ส่งเป้าหมายให้ตัวควบคุมมอเตอร์
```

กฎสำคัญคือ **อุณหภูมิสูงมีสิทธิ์ปิดเหนือกฎแสง** ดังนั้นหากอุณหภูมิ 32°C แต่แสงเพียง 100 lux ระบบสมดุลปัจจุบันยังเลือกเป้าหมาย 15%

## Confirmation

ระบบไม่ควรขยับจากค่าครั้งเดียว เพราะเซ็นเซอร์อาจแกว่งหรือมี noise

ตัวอย่างเมื่อกำหนด 3 ครั้ง:

```text
15%, 15%, 15% → ยืนยันเป้าหมาย 15%
15%, 40%, 15% → เริ่มนับเป้าหมายใหม่
```

ค่าตัวอย่างเดิมจากการ render ซ้ำต้องไม่นับเพิ่ม ต้องเป็นข้อมูลเซ็นเซอร์รอบใหม่จริง

## Cooldown

Cooldown เริ่มหลังจากมอเตอร์ทำงานและหยุดแล้ว ระหว่าง Cooldown:

- ไม่ส่งคำสั่ง Auto ใหม่
- ไม่สะสม Confirmation สำหรับคำสั่งถัดไป
- STOP และ fault ยังต้องทำงานตามปกติ

สถานะ Cooldown สามารถกู้กลับหลังรีเฟรชหน้าเว็บได้ แต่จำนวน Confirmation เก่าไม่ควรถูกกู้กลับมา

## การจัดการข้อมูลผิดปกติ

- เซ็นเซอร์ที่เปิดใช้ไม่มีค่า → `waiting` และไม่สร้างคำสั่ง
- ช่วงแสงไม่ต่อกันหรือทับกัน → Preset ไม่ผ่านการตรวจ
- เป้าหมายอยู่นอก 0–100% → Preset ไม่ผ่านการตรวจ
- ไม่มีทั้งกฎอุณหภูมิและกฎแสง → Preset ไม่ผ่านการตรวจ
- คำสั่งล้มเหลวหรือ ESP32 ไม่ยืนยัน → เข้า fault และไม่ส่งซ้ำทันที

## จุดแข็ง

- เข้าใจและอธิบายให้ผู้ใช้ได้ง่าย
- ผู้ใช้เลือกชุดสำเร็จรูปได้
- ใช้งานจริงใน ESP32 และปิดหน้าเว็บได้
- มี Confirmation และ Cooldown ลดการขยับถี่
- ส่งเป้าหมายแบบ Absolute จึงตรวจผลกับ Encoder ได้ตรงไปตรงมา

## ข้อจำกัด

- ค่าอุณหภูมิและแสงไม่ได้ผสมเป็นบริบทเดียวกันจริง ๆ
- เมื่อร้อนถึงเกณฑ์ ระบบปิดโดยไม่สนใจว่าห้องมืดอยู่หรือไม่
- เป้าหมายอาจเปลี่ยนไกลในคำสั่งเดียว เช่น 90% ไป 15%
- ช่วงค่าเป็นขั้นบันได การเปลี่ยนเล็กน้อยบริเวณขอบช่วงอาจทำให้เป้าหมายเปลี่ยนมาก

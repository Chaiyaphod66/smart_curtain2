# Model A: Closed-loop Auto

## สถานะ

Model A ในโครงการหมายถึงกฎ Closed-loop ชุดเดียว โดย Firmware ESP32 (`smart_curtain_esp32/src/main.cpp`) เป็นผู้ตัดสินใจและสั่งม่านต่อเนื่องแม้ปิดเว็บ เมื่อบันทึกผ่าน `/auto/model-a` และเปิดด้วย `/auto/enable` แล้ว

หน้า Dev ใช้แสดงผลคำนวณและสถานะเพื่อช่วยตรวจสอบกฎ ไม่ใช่ Model A อีกตัวหนึ่ง วงรอบจริงบน ESP32 ยืนยันผล 2 รอบ ขยับทีละ Step รอให้มอเตอร์หยุด และพัก 15 วินาทีก่อนประเมินรอบใหม่ หากเซ็นเซอร์ไม่พร้อม ลิมิตผิดปกติ หรือเกิด motor fault ระบบจะไม่สร้างคำสั่งใหม่และเข้าสู่สถานะที่ปลอดภัย

ชื่อ Model A ในเอกสารนี้หมายถึงโมเดลทดลองของโปรเจกต์ ไม่ได้หมายความว่าเป็นมาตรฐานสากลหรือผ่านการรับรองแล้ว

## แนวคิด

Model A ไม่ใช้คะแนนแบบ “อุณหภูมิ 60% + แสง 40%” แต่แบ่งหน้าที่ดังนี้:

1. อุณหภูมิเลือกงบแสงสูงสุดที่ยอมรับได้
2. ความเข้มแสงตัดสินว่าจะเปิด ปิด หรือคงตำแหน่ง
3. หากต้องขยับ จะเปลี่ยนตำแหน่งทีละ Step
4. อ่านผลใหม่ แล้วตัดสินใจรอบถัดไป

นี่เป็น Closed-loop เพราะทุกคำสั่งใช้ตำแหน่งและข้อมูลรอบล่าสุด ไม่สั่งกระโดดถึงค่าปลายทางทันที

## Profile ปัจจุบัน

| อุณหภูมิ | งบแสงสูงสุด |
|---|---:|
| ต่ำกว่า 26°C | 3,000 lux |
| 26–ต่ำกว่า 28°C | 2,500 lux |
| 28–ต่ำกว่า 30°C | 1,500 lux |
| 30–ต่ำกว่า 31°C | 900 lux |
| ตั้งแต่ 31°C | 600 lux |

ค่าประกอบ:

| ตัวแปร | ค่า |
|---|---:|
| แสงต่ำ | 200 lux |
| จุดเริ่มกฎร้อนแต่มืด | 30°C |
| Hysteresis ของช่วงอุณหภูมิ | ±0.5°C |
| Step เริ่มต้น | 15% |
| Step ต่ำสุด | 5% |

## ลำดับการตัดสินใจ

```text
ถ้าไม่มีอุณหภูมิหรือแสง
    → รอข้อมูลและไม่สร้างเป้าหมาย

เลือกช่วงอุณหภูมิโดยใช้ Hysteresis

ถ้าอุณหภูมิ ≥ 30°C และแสง < 200 lux
    → คงตำแหน่ง เพราะห้องมืดอยู่แล้ว

ถ้าแสง > งบแสงสูงสุดของช่วงอุณหภูมิ
    → ปิดลงหนึ่ง Step

ถ้าแสง < 200 lux
    → เปิดขึ้นหนึ่ง Step

นอกเหนือจากนั้น
    → คงตำแหน่ง
```

ถ้าต้องเปิดหรือปิดแต่ไม่มีตำแหน่ง Encoder ปัจจุบัน ระบบจะไม่สร้างเป้าหมาย เพราะไม่รู้ว่าจะบวกหรือลบ Step จากจุดใด

## Hysteresis ของอุณหภูมิ

Hysteresis ป้องกันการสลับช่วงเมื่ออุณหภูมิแกว่งอยู่ใกล้ขอบ เช่น 29.9, 30.0, 29.9°C

เมื่อกำลังอยู่ช่วงต่ำกว่า 30°C ระบบต้องสูงผ่านขอบพร้อมระยะ Hysteresis ก่อนเปลี่ยนขึ้น และเมื่อลดลงก็ต้องต่ำกว่าขอบอีกด้านก่อนเปลี่ยนกลับ

สถานะช่วงอุณหภูมิจึงต้องถูกเก็บข้ามการอ่านหนึ่งรอบ ไม่สามารถคำนวณจากค่าปัจจุบันเพียงค่าเดียวได้

## Adaptive Step

Step เริ่มต้นคือ 15% หากทิศทางใหม่ตรงข้ามกับทิศทางก่อนหน้า หมายความว่าระบบอาจขยับข้ามจุดสมดุล จึงลด Step:

```text
15% → 7% → 5%
```

ถ้าอยู่ที่ Step ต่ำสุดแล้วยังต้องกลับทิศอีก ระบบตั้งสถานะ `resolutionLimited` และหยุดเสนอคำสั่ง จนกว่าจะ Reset การทดลอง

วิธีนี้ป้องกันการเปิด–ปิดสลับไปมาไม่จบ แต่ในอนาคตอาจต้องเพิ่มเงื่อนไขออกจากสถานะนี้เมื่อสภาพแวดล้อมเปลี่ยนมากพอ

## ตัวอย่าง

สมมติว่าตำแหน่งปัจจุบันคือ 50%:

| อุณหภูมิ | แสง | ผล |
|---:|---:|---|
| 32°C | 100 lux | คง 50% เพราะร้อนแต่มืด |
| 32°C | 1,200 lux | ปิดหนึ่ง Step ไป 35% |
| 29°C | 800 lux | คง 50% เพราะยังไม่เกินงบ 1,500 lux |
| 27°C | 100 lux | เปิดหนึ่ง Step ไป 65% |

ตำแหน่งเป้าหมายทุกครั้งต้องถูก clamp ให้อยู่ใน 0–100%

## State ที่ Model A ต้องจำ

- ช่วงอุณหภูมิล่าสุด
- ขนาด Step ปัจจุบัน
- ทิศทางล่าสุด
- สถานะ `resolutionLimited`

Runtime ทดลองเก็บ State ในหน้าเว็บและ Reset เมื่อเริ่ม Lab ใหม่หรือโหลดหน้าใหม่ ส่วนโหมดบน ESP32 เก็บ State ระหว่างทำงานในบอร์ด จึงทำงานต่อได้เมื่อปิดเว็บ การตั้งค่าและสถานะเปิด Auto บันทึกในหน่วยความจำของบอร์ด แต่หลังบอร์ดรีสตาร์ตต้อง Homing ใหม่ก่อนขยับ และ Step/ช่วงอุณหภูมิเริ่มต้นใหม่

## จุดแข็ง

- เชื่อมอุณหภูมิและแสงเข้าด้วยกันโดยไม่ต้องสร้างคะแนนที่อธิบายยาก
- ไม่ปิดม่านเพราะร้อนอย่างเดียวเมื่อห้องมืด
- ขยับทีละขั้น ลดการกระโดดไกล
- ลด Step เมื่อกลับทิศ จึงละเอียดขึ้นใกล้จุดสมดุล
- แสดงเหตุผลการตัดสินใจให้ผู้พัฒนาตรวจได้

## ข้อจำกัดและสิ่งที่ยังไม่รู้

- ค่า lux และอุณหภูมิยังเป็นค่าตั้งต้นจากแบบจำลอง ต้องยืนยันกับห้องจริง
- ยังไม่คำนึงถึงความชื้น ทิศทางแสง เวลา หรือความต้องการเฉพาะผู้ใช้
- Confirmation 2 รอบและ Cooldown 15 วินาทีมีทั้งใน Runtime เว็บและ firmware สำหรับ Model A; ต้องตรวจสอบพฤติกรรมจริงบนฮาร์ดแวร์ก่อนใช้งานโดยไม่เฝ้า
- State ระหว่างทำงานใน ESP32 ไม่ได้คงค่าข้ามการรีสตาร์ต ยกเว้นการตั้งค่าเปิดโหมด
- ยังไม่กำหนดชัดว่าจะฟื้นจาก `resolutionLimited` โดยอัตโนมัติเมื่อใด
- การขยับหลาย Step ต้องป้องกันไม่ให้สะสมคำสั่งขณะมอเตอร์ยังทำงาน

## เงื่อนไขของการทดสอบต่อเนื่องบนเว็บ

1. ต้องเลือก Auto Lab และใช้ข้อมูลจริงจาก ESP32
2. Encoder ต้องคาลิเบรตและ Position control ต้องพร้อม
3. FC-33 ต้องเปิดใช้งาน ไม่มี limit conflict และไม่มี motor fault
4. Always-on Auto ของ Logic ปัจจุบันต้องปิดอยู่
5. ส่งคำสั่งได้ครั้งละหนึ่งเป้าหมาย และรอผลการหยุดจริงก่อนคำนวณรอบใหม่
6. ต้องเปิดหน้า Dev เฝ้าระหว่างทดสอบ การซ่อนแท็บจะยกเลิก Runtime
7. STOP, timeout, FC-33 และ fault มีสิทธิ์เหนือ Model A เสมอ

## การเปิด Model A บน ESP32

1. อัปโหลด firmware ที่รองรับ `/auto/model-a` และคาลิเบรต/Homing ให้ตำแหน่ง Encoder พร้อม
2. ตรวจ FC-33 ทั้งสองด้าน, STOP, ข้อมูลอุณหภูมิ/แสง และสถานะ fault ภายใต้การเฝ้าดู
3. ในหน้า Dev เลือก Auto Lab แล้วกด **บันทึกและเปิดบน ESP32** ระบบจะบันทึก Profile คงที่ในบอร์ดก่อนเปิด Auto
4. ตรวจ `/status` ว่า `auto.presetId` เป็น `model-a`, `auto.enabled` เป็น `true` และติดตาม `auto.phase`/`auto.reason`
5. หลังทดสอบความปลอดภัยผ่านแล้วจึงปิดเว็บได้ หากเกิด motor fault ระบบปิด Auto; หลังบอร์ดรีสตาร์ตต้อง Homing ก่อนเริ่มเคลื่อนอีกครั้ง

การปิดหน้าเว็บไม่เท่ากับการกด STOP หากต้องการหยุดให้ใช้ปุ่ม STOP หรือปิด Auto โดยตรง อย่าปล่อยม่านทำงานโดยไม่มีคนเฝ้าจนกว่าจะทดสอบฮาร์ดแวร์จริงครบ รวมถึงกรณีเซ็นเซอร์หาย, ลิมิต, เบรก, รีสตาร์ต และการเชื่อมต่อหลุด

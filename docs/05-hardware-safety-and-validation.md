# ฮาร์ดแวร์ การหยุดม่าน และแผนตรวจผล

อัปเดต: 30 ตุลาคม 2569 — ต้นแบบ ESP32 + L298N + Encoder + FC-33 สองตัว

## สิ่งที่โค้ดทำอยู่

- Firmware อยู่ในโปรเจกต์ข้างเคียง `../smart_curtain_esp32/src/main.cpp` ไม่ได้รวมอยู่ใน repository เว็บนี้
- GPIO25 ควบคุม ENA/PWM ของ L298N, GPIO16/17 กำหนดทิศทาง, GPIO32/33 รับ Encoder A/B และ GPIO27/26 รับ FC-33 ด้านปิด/เปิด
- ความเร็วปัจจุบัน `TEST_SPEED = 14` จาก PWM 8 บิต (14/255 ประมาณ 5.5% duty) ที่ 5 kHz **ยังไม่เปลี่ยนค่า** เพราะความเร็วเชิงกลและกระแสของชุดม่านจริงต้องวัดก่อน
- การตรวจลิมิตขณะมอเตอร์วิ่งใช้ระดับสัญญาณ raw ก่อน debounce 40 ms; debounce ใช้กับสถานะที่แสดงและนับจำนวนการกระตุ้น จึงไม่ควรสรุปว่า 40 ms คือเวลารอหยุด
- เมื่อพบลิมิต Firmware สั่ง active brake ที่ duty 255 เป็นเวลา 100 ms; การหยุดที่เป้าหมาย Encoder ใช้ duty 255 เป็นเวลา 80 ms ค่าพวกนี้ยังไม่ปรับ เพราะต้องตรวจพิกัดกระแส/อุณหภูมิของมอเตอร์ ไดรเวอร์ และแหล่งจ่าย
- Jog มี timeout 250 ms; วิ่งหาลิมิต 10 s; สั่งตำแหน่ง 15 s พร้อม no-pulse timeout 1.2 s ค่าตั้งนี้เป็นของต้นแบบ ไม่ใช่การรับรองว่าปลอดภัยสำหรับทุกระยะม่าน
- รอบนี้เลื่อนการอ่าน DHT22/BH1750 ออกไปขณะมอเตอร์วิ่ง และกลับมาอ่านหลังหยุด เพื่อลดงานบล็อกใน `loop()` ระหว่างที่ต้องตรวจลิมิต ไม่ได้เปลี่ยนความแรงของมอเตอร์หรือวงจรเบรก
- Firmware `0.12.2` ตรวจการเปลี่ยนจาก Wi-Fi Station ที่เชื่อมต่ออยู่เป็นหลุด หากมอเตอร์กำลังทำงานจะใช้ active brake แบบเดียวกับการหยุดตำแหน่ง จากนั้นปิด Auto บันทึกสาเหตุ `network-lost` และรอให้ผู้ใช้เปิด Auto ใหม่เอง
- หลังล้าง Calibration ขณะอยู่ที่ลิมิต Firmware อนุญาตให้ Homing ออกจากลิมิตด้วยระยะพัลส์แบบค่าสัมบูรณ์ โดยยังคงเพดานระยะและ timeout; เมื่อมีค่าระยะที่เชื่อถือได้แล้วจะกลับไปตรวจเครื่องหมายทิศทาง Encoder ตามปกติ
- ทุกครั้งที่ ESP32 รีบูต มอเตอร์เริ่มในสถานะหยุดและ `auto.enabled` ถูกบังคับเป็น `false` โดยยังเก็บพรีเซ็ตเดิมไว้ การปิดหน้าเว็บอย่างเดียวไม่ทำให้ Auto หยุด เพราะ Logic ยังทำงานบน ESP32

## ทำไมยังอาจรู้สึกว่าช้า

1. **ม่านจริงหยุดช้า:** อาจเกิดจากลูปตรวจลิมิต งาน HTTP/เซ็นเซอร์ที่บล็อก, โมเมนตัมของชุดม่าน หรือระยะวาง FC-33 ต้องวัดแยกกัน
2. **หน้าเว็บขึ้นสถานะช้า:** หน้าเว็บอ่าน `/status` เป็นรอบ ๆ; ภาพบนจอจึงอาจตามหลังการหยุดจริง อย่าใช้เวลาบนหน้าจอแทนเวลาเบรกจริง
3. **ม่านเคลื่อนช้า:** PWM 14/255 เป็นค่าทดลองที่ต่ำมาก แต่การเพิ่ม duty โดยไม่วัดกระแส/อุณหภูมิและระยะหยุดอาจเพิ่มความเสี่ยง ไม่ควรเพิ่มเพียงเพราะรู้สึกช้า

## เกณฑ์ทดสอบก่อนเขียนผลรายงาน

ทำกับพื้นที่โล่ง ไม่มีคนหรือสิ่งของในแนวม่าน มีผู้เฝ้าดูและวิธีตัดไฟมอเตอร์ที่เอื้อมถึง ไม่ทดสอบแบบปล่อยทำงานลำพัง

| การทดสอบ | บันทึกผล |
| --- | --- |
| ตรวจ GPIO26/27 โดยไม่สั่งมอเตอร์ | ค่า raw และ active เปลี่ยนถูกด้าน ไม่มี conflict |
| Jog ระยะสั้นทั้งสองทิศ | ทิศจริง, ระยะทาง, กระแส, อุณหภูมิ L298N และมอเตอร์ |
| วิ่งเข้าลิมิตทีละด้าน | เวลาจาก FC-33 active ถึง ENA หยุดจ่าย/เบรก, ระยะไหลต่อจริง, stop reason ใน `/status` |
| สั่ง STOP ระหว่างเคลื่อน | เวลาหยุดจริงและระยะไหลต่อ เทียบกับลิมิต |
| ทดสอบ encoder ไม่ส่ง pulse/ลิมิตไม่ทำงาน | timeout หยุดตามที่ตั้ง โดยไม่ชนโครงสร้างจริง |
| ตัด/คืนไฟ | ไม่มีมอเตอร์หมุนเอง; `/status` แสดง `restart-manual`; Auto ปิดและต้อง Homing ก่อนสั่งตำแหน่ง |
| Wi-Fi Station หลุดขณะ Manual เคลื่อน | มอเตอร์หยุด; `lastStopReason = network-lost`; หลังเชื่อมใหม่ยังอยู่ Manual |
| Wi-Fi Station หลุดขณะ Auto เคลื่อนหรือรอ | Auto ปิดและบันทึก `enabled = false`; ไม่เปิดกลับเองหลัง Wi-Fi กลับมา |
| ปิดหน้าเว็บขณะ Auto ทำงาน | Wi-Fi ของ ESP32 ยังเชื่อมอยู่และ Auto ทำงานต่อบนบอร์ดตามปกติ |

ถ้าจะรายงานว่า "หยุดเร็วขึ้น" ให้ทดสอบ firmware ก่อน–หลังบนชุดฮาร์ดแวร์เดียวกันอย่างน้อยหลายรอบ และแยก **เวลา detect**, **เวลาสั่ง ENA**, **เวลาหยุดจริง** อย่าอนุมานจาก build ผ่านหรือความเร็วของ UI

## ข้อจำกัดความปลอดภัย

FC-33 กับการหยุดด้วยซอฟต์แวร์บนไมโครคอนโทรลเลอร์เป็นชั้นป้องกันของต้นแบบ ไม่ใช่ safety-rated end stop หรือ emergency stop อิสระ ปุ่ม "หยุดมอเตอร์" บนเว็บส่ง HTTP และ `stopMotor()` ปกติไม่ได้สั่ง active brake จึงไม่ควรใช้แทนสวิตช์ตัดไฟฉุกเฉิน งาน HTTP และไลบรารีอื่นยังอาจหน่วงลูปได้ การใช้งานจริงที่คนหรือทรัพย์สินอยู่ในแนวม่านควรมีการตัดกำลังมอเตอร์ทางฮาร์ดแวร์ที่เป็นอิสระ รวมถึงตรวจพิกัดอะแดปเตอร์ สาย ฟิวส์ และการระบายความร้อนโดยผู้มีความรู้ด้านไฟฟ้า

อย่าเพิ่ม duty เบรกเป็นค่าสูงกว่าเดิมโดยไม่มีการวัด: [ST L298 datasheet](https://www.st.com/resource/en/datasheet/l298.pdf) เตือนว่าการเบรกเร็วทำให้กระแสพุ่งได้ และต้องอยู่ในพิกัดของไดรเวอร์

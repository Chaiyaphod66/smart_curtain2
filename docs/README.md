# บันทึกการพัฒนา Smart Curtain

อัปเดตล่าสุด: 31 ตุลาคม 2569

โฟลเดอร์นี้เก็บคำอธิบายระบบสำหรับกลับมาอ่านและพัฒนาต่อ โดยแยกแนวคิดออกจากโค้ดเพื่อไม่ให้รายละเอียดสำคัญกระจายอยู่ในแชต

## ลำดับที่แนะนำให้อ่าน

1. [ภาพรวมระบบ Auto](01-auto-system-overview.md) — ทำความเข้าใจ Manual, Auto บน ESP32 และเส้นทางข้อมูลตั้งแต่เว็บถึงมอเตอร์
2. [Auto Preset ปัจจุบัน](02-current-auto-preset.md) — Logic ที่ ESP32 ใช้งานจริง เกณฑ์ตัดสินใจ Confirmation และ Cooldown
3. [Model A: Closed-loop Auto](03-model-a-closed-loop.md) — Logic ที่เชื่อมอุณหภูมิกับงบแสง ขยับม่านทีละขั้น และทำงานบน ESP32
4. [เปรียบเทียบและแผนพัฒนาต่อ](04-comparison-and-next-steps.md) — เปรียบเทียบ Auto Preset กับ Model A และบันทึกแผนพัฒนาเดิม
5. [ฮาร์ดแวร์และการตรวจ Safety](05-hardware-safety-and-validation.md) — ค่าความเร็ว/เบรกปัจจุบัน ข้อจำกัด และรายการวัดผลกับม่านจริง
6. [แผนที่โค้ดสำหรับรายงาน](06-report-code-map.md) — เว็บ Firmware และจุดที่ควรอ้างอิงในบทอธิบายระบบ
7. [แผนพัฒนาโครงการเดิม](PROJECT_PLAN.md) — แผนภาพรวมตั้งแต่เริ่มต้นเว็บ เซ็นเซอร์ API และฮาร์ดแวร์

## สถานะสั้น ๆ

- **Auto Preset ปัจจุบัน** ทำงานจริงบน ESP32 และทำงานต่อได้เมื่อปิดหน้าเว็บ
- **Model A** ทำงานใน Firmware ESP32 และทำงานต่อได้เมื่อปิดหน้าเว็บ; หน้า Dev ใช้ตรวจเหตุผลและสถานะของกฎเดียวกัน
- หน้าเว็บใช้ตั้งค่า เปิด/ปิด และตรวจสถานะ ส่วนวงรอบควบคุม Auto จริงอยู่บน ESP32
- ระบบ Auto ทุกแบบต้องผ่านชั้นความปลอดภัยของ Encoder, FC-33, STOP, timeout และ motor fault เสมอ

## คำศัพท์ที่ใช้ในเอกสาร

- **ตำแหน่งม่าน**: ค่าสูงหมายถึงเปิดมากขึ้น เช่น 90% เปิดมากกว่า 15%
- **เป้าหมายแบบ Absolute**: สั่งไปยังตำแหน่งตายตัว เช่น 40%
- **เป้าหมายแบบ Step**: ขยับจากตำแหน่งปัจจุบันทีละช่วง เช่น ปิดลง 15%
- **Dry run / Preview**: คำนวณผลแต่ไม่สั่งมอเตอร์
- **Always-on Auto**: Auto ที่ทำงานบน ESP32 แม้ไม่ได้เปิดเว็บ

> เอกสารนี้เป็นบันทึกทางวิศวกรรมของต้นแบบ ไม่ใช่คู่มือรับรองความปลอดภัยของผลิตภัณฑ์จริง
